### Findings

#### Should fix

1. **The ticked declarations of PRs #1 and #2 are not on `main`.** Both merge commits have only the default message: `Merge pull request #N from …` plus the PR title (`git log -1 --format=%B 05ff570` and `1ce757d`). CONTRIBUTING.md line 33 and SETUP.md section 2 say the merge message is "Pull request title and description", so that the ticks reach the history. The PR #2 description itself asked Pascal to switch the setting. aidecl doesn't run the `AI badge` workflow, so no badge is wrong today, but the record those two PRs were meant to leave is missing. Set the merge message in aidecl's settings before the next merge. The two existing merges can't be fixed without rewriting history; leaving them is fine, since `AIDECL.toml` declares the files.

2. **`github-actions[bot]` is exempt from the PR check, and AI agents running in Actions open PRs as that account.** `ai-declaration.yml` line 28 skips the job for `dependabot[bot]` and `github-actions[bot]` (the latter for CompatHelper). A workflow that opens PRs with `GITHUB_TOKEN`, which includes agent actions run in CI, also appears as `github-actions[bot]`, and a skipped required check counts as passed. So exactly the PRs the rule targets can bypass it. Narrow the exemption, for example to `github-actions[bot]` with a head branch starting with `compathelper/`.

3. **Leftovers from the 815acaf reviews that are still open:**
   - No `v0.3.0` tag exists (`git ls-remote --tags` is empty), but `aidecl.yml` in aidecl and in the org template suggest `aidecl-ref: v0.3.0`, and SETUP.md suggests tagging it. Uncommenting the line breaks the install step.
   - Inline `AI-Review: A-` in a version-3 repo: `lint` says "A- is now A0; run 'aidecl migrate'" (`model.py:185`), and `migrate` then answers "convert the old tags in these files by hand". Reproduced. The hint should say "use A0" when `AIDECL.toml` is already version 3.
   - `AI-Review = "A-"` inside a version-3 `AIDECL.toml` gets no hint (`config.py:358`), unlike `[policy]`, inline tags and the PR check.
   - `aidecl init` still suggests `exclude = ["docs/build/**"]` and doesn't mention `reviews/**`, although CONTRIBUTING.md says the review folder should be excluded.
   - The org PR template's checklist still says "Tests pass locally (`Pkg.test()`)", which is Julia-specific; PR #2 edited it by hand to `pytest -q`.

#### Nice to fix

4. **The badge parser and the PR check treat inline code differently.** The PR check removes inline code before it looks for `<!--` (`ai-declaration.yml` line 121); the badge workflow removes `<!--…-->` from the whole message without regard to backticks (`ai-badge.yml` line 84). A description that mentions `` `<!--` `` in inline code and no longer contains the template's own comments passes the check, but the badge workflow hides everything after it and doesn't count the commit. Reproduced with the current template. This is rare, but most likely in exactly this org's PRs about the template. Removing inline code first in `ticked_levels()` makes the two agree.

5. **`annotate -H TODO` without `--reviewed-by` writes no `Reviewed-by` at all.** That is intended (`test_annotate_todo_without_reviewed_by`), and `lint` fails on the TODO. But when a person later replaces only `Human-Review = "TODO"` with a level, `lint` fails again with "Human-Review needs Reviewed-by". Writing `Reviewed-by = ["TODO"]` automatically when `-H TODO` is given without names would put both things to fill in side by side.

6. **`annotate --inline` doesn't check that the file is inside `--root`.** `aidecl --root p2 annotate x.py --inline …` tagged `./x.py` outside `p2`, checked against `p2`'s policy. The TOML mode refuses paths outside the root (`_pattern`); the inline mode could do the same.

7. **A level in the wrong case makes an inline block invisible.** Keys are case-insensitive, but values are not, and a block needs a valid level line to count. A header `# AI-Generation: g2` is silently ignored, and the file falls back to `AIDECL.toml` (or to "no declaration"). Reproduced. Either accept the level case-insensitively or report a near-miss block.

8. **The repo's own `AIDECL.toml` can be tidied when it's raised to A2:**
   - Annotation 3 (`README.md`, `src/aidecl/model.py`) repeats annotation 2 word for word; it changes nothing.
   - Annotation 1 names the model `Claude (Anthropic), claude-opus-5-5`; the README, CONTRIBUTING.md and the project rules use `Claude Opus 5.5 (Anthropic)`.
   - `Reviewed-by` is a string in annotation 1 and a list in 2 and 3. Both are valid.

#### Nits

9. In `ai-declaration.yml`, the error path calls `summary…write()` without `await` (line 260) before `setFailed`. It works because Node waits for the pending write, but awaiting it is clearer.
10. The check rejects any visible line that starts with `Reviewed-by:`, `AI-Review:` and so on, including prose or a `Reviewed-by:` someone adds out of habit. The error message explains it, and a code block avoids it.
11. `policy` examples in `model.py` (comment on line 79, error message on line 104) still use `ai = "A0"`, which is a no-op minimum on the current scale.
